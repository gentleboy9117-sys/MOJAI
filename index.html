2 문제 인식기존 방식의 한계

기존 도구로는 해결이 어려웠습니다

포털 검색의 한계

  • "검찰청 관할"이라는 개념이 없어 지역·청별 구분 불가
  • 같은 사건 기사가 수십 건씩 반복 노출

수작업 정리의 한계

  • 문서에 수기로 옮겨 적는 일회성 정리 — 축적·재사용 불가
  • 어제와 오늘의 추이 비교가 어려움

서식 관리의 한계

  • 과거 문서를 찾아 복사·수정하는 방식
  • 최신 양식·문체와 어긋나는 일 발생
이 세 가지 한계를 하나의 도구로 해결하도록 설계했습니다 — 관할을 아는 수집·분류, 축적되는 통계, 표준 양식 자동 생성.

4 구현 방법개발 방식

개발 경험 없는 검사가 AI와의 대화로 완성했습니다

Claude Code 바이브 코딩

  • 화면·API·DB 설계·분류 로직을 대화로 직접 구현
  • 외주 없이 기획부터 배포까지 1인 수행
  • Next.js · TypeScript · Prisma · KRDS 디자인 토큰
  • 실서비스 운영 중 — 이 자리에서 즉시 시연 가능

정확성 확보 장치

  • 분류마다 신뢰도·판단 근거 저장 → 사후 검증 가능
  • 화면 간 동일 데이터 사용 → 수치 불일치 차단
  • 고정 데이터는 정적 스냅샷으로 제공 → 접속 즉시 응답
바이브 코딩이란? 개발자가 아닌 사람이 AI에게 말로 요구사항을 설명하면 AI가 코드를 작성하는 개발 방식입니다. 본 시스템은 이 방식으로 검사 1인이 개발했습니다.

KICS 등 기존 시스템과 완전 분리

KICS: 수사·재판 정보를 다루는 형사사법정보시스템

  • 형사사법시스템을 대체·연동하지 않는 독립 보조도구
  • 수사정보 미사용 — 공개 뉴스·공식 발표자료·공개 집회일정만 취급

임의 사실 생성 차단 (RAG)

  • 사실관계는 입력값과 공개자료만 사용
  • 발표자료는 유사 양식의 구조·문체만 참고 — 내용 복사 없음

운영 보안

  • 권한관리(RBAC) · 감사로그 · 외부 전송 최소화
  • 망분리 환경은 내부망 LLM 교체로 대응 — Mock/상용/내부망 3단 교체 구조

책임 구조

  • AI는 수집·정리·초안 보조까지만 수행 — 판단하지 않음
  • 분류마다 신뢰도·근거 저장, 최종 검토·사용 결정은 담당자
